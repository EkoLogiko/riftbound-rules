2. Make relevant choices. ^cr-355

<details class="rule-ref"><summary title="Core rule 355 · PDF page 47" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355 · PDF page 47</div></details>

If the [[Card|card]] has an effect that specifies a choice or instructs an action that is not a [[Costs|cost]] "As I am played," or “As you [[Play|play]] me,” those choices or actions are made or performed now. ^cr-355-1

<details class="rule-ref"><summary title="Core rule 355.1 · PDF page 47" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.1 · PDF page 47</div></details>

This includes the choice of whether or not to pay an Optional [[Additional Cost]]. ^cr-355-1-a

<details class="rule-ref"><summary title="Core rule 355.1.a · PDF page 47" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.1.a · PDF page 47</div></details>

For [[Unit|Units]], choose a valid [[Location]] where that Unit will enter upon being Played. ^cr-355-2

<details class="rule-ref"><summary title="Core rule 355.2 · PDF page 47" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.2 · PDF page 47</div></details>

By default, Valid [[Location|locations]] include the controller’s [[Base]] or a [[Battlefield]] the controller controls. ^cr-355-2-a

<details class="rule-ref"><summary title="Core rule 355.2.a · PDF page 47" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.2.a · PDF page 47</div></details>

Some [[Game Effect|Game Effects]] may grant players permission to [[Play|play]] [[Unit|Units]] to [[Location|locations]] that are not normally Valid. Such locations become Valid for the purposes of Playing the Unit. ^cr-355-2-b

<details class="rule-ref"><summary title="Core rule 355.2.b · PDF page 47" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.2.b · PDF page 47</div></details>

For [[Spell|Spells]] and [[Ability|Abilities]] with a bulleted list of modes to choose from, make the appropriate choices now. ^cr-355-3

<details class="rule-ref"><summary title="Core rule 355.3 · PDF page 47" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.3 · PDF page 47</div></details>

For [[Spell|Spells]] and [[Ability|Abilities]] that [[Move]] one or more [[Unit|Units]], choose a valid [[Location]] as the Move Destination for each Move that will be performed. ^cr-355-4

<details class="rule-ref"><summary title="Core rule 355.4 · PDF page 47" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.4 · PDF page 47</div></details>

A valid [[Location]] for a [[Move]] Effect is one other than the [[Unit|Units]]’ current Location where they are allowed to be present. ^cr-355-4-a

<details class="rule-ref"><summary title="Core rule 355.4.a · PDF page 47" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.4.a · PDF page 47</div></details>

If a [[Card|card]] requires you to specifically choose one or more [[Game Object|Game Objects]], that choice is made now. ^cr-355-5

<details class="rule-ref"><summary title="Core rule 355.5 · PDF page 47" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.5 · PDF page 47</div></details>

This does not include [[Card|cards]] that affect one or more [[Game Object|Game Objects]] based on criteria. ^cr-355-5-a

**Example:** "[[Stun]] a [[Unit|unit]] at a [[Battlefield|battlefield]]" is a Choice.

**Example:** "[[Kill]] all [[Gear|gear]]" is not a Choice.

<details class="rule-ref"><summary title="Core rule 355.5.a · PDF page 47" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.5.a · PDF page 47</div></details>

This does not include making choices for [[Triggered Ability|Triggered Abilities]] of [[Permanent|permanents]], or Delayed or [[Reflexive Trigger|Reflexive Triggers]] generated by the item being finalized, even if those [[Ability|abilities]] trigger when the [[Chain|chain]] item is played. ^cr-355-5-b

**Example:** A [[Unit|unit]] with a [[Triggered Ability|triggered ability]] that says "When I'm played, [[Kill|kill]] a unit" does not require you to choose a target as it's played. The target will be chosen when the [[Ability|ability]] triggers.

**Example:** Targon’s Peak reads “When you [[Conquer|conquer]] here, [[Ready|ready]] up to 2 [[Rune|runes]] at the end of this [[Turn|turn]].” Readying up to 2 runes at the end of the turn is the effect of a [[Delayed Trigger|delayed trigger]]; any choices involved are not made when finalizing the [[Conquer Effect|conquer effect]] but when finalizing the resulting delayed trigger at the end of the turn.

See [[Triggered Ability#^cr-382|Triggered Abilities]] for more information.

### Targeting

^cr-355-6

<details class="rule-ref"><summary title="Core rule 355.6 · PDF page 47" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.6 · PDF page 47</div></details>

When a [[Card|card]] Chooses one or more specific [[Game Object|Game Objects]], Players, or [[Zone|Zones]] to affect, they are Targeted unless indicated otherwise by the rules in this section. If a card Picks one or more specific Game Objects, Players, or zones, they are not Targeted. ^cr-355-7

<details class="rule-ref"><summary title="Core rule 355.7 · PDF page 47" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.7 · PDF page 47</div></details>

In order to put a [[Spell|spell]] or [[Ability|ability]] on the [[Chain|chain]], valid choices must be made for all targets. ^cr-355-8

<details class="rule-ref"><summary title="Core rule 355.8 · PDF page 47" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.8 · PDF page 47</div></details>

A target is a valid choice if it meets all of the following requirements: ^cr-355-9

<details class="rule-ref"><summary title="Core rule 355.9 · PDF page 48" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.9 · PDF page 48</div></details>

It is a [[Permanent|permanent]] or [[Rune|rune]] on [[Board|the board]], a finalized [[Spell|spell]] or [[Ability|ability]] on the [[Chain|chain]], a player or [[Zone|zone]], or a [[Game Object|game object]] specified explicitly or implicitly as being in some other zone. e.g., “[[Kill]] a [[Unit|unit]]” targets a unit on the board. e.g., “[[Recycle]] a unit from your [[Trash|trash]]” targets a unit [[Card|card]] in your trash. ^cr-355-9-a

<details class="rule-ref"><summary title="Core rule 355.9.a · PDF page 48" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.9.a · PDF page 48</div></details>

“[[Unit]],” “[[Gear|gear]],” and “[[Rune|rune]]” refer to objects on [[Board|the Board]] unless specified otherwise. ^cr-355-9-a-1

<details class="rule-ref"><summary title="Core rule 355.9.a.1 · PDF page 48" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.9.a.1 · PDF page 48</div></details>

“[[Spell]]” and “[[Ability|ability]]” refer to finalized objects on the [[Chain]] unless specified otherwise. ^cr-355-9-a-2

<details class="rule-ref"><summary title="Core rule 355.9.a.2 · PDF page 48" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.9.a.2 · PDF page 48</div></details>

“Facedown [[Card|card]]” refers to a card in a [[Facedown Zone]] unless specified otherwise. ^cr-355-9-a-3

<details class="rule-ref"><summary title="Core rule 355.9.a.3 · PDF page 48" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.9.a.3 · PDF page 48</div></details>

“[[Legend]]” refers to a legend in the [[Legend Zone]]. ^cr-355-9-a-4

<details class="rule-ref"><summary title="Core rule 355.9.a.4 · PDF page 48" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.9.a.4 · PDF page 48</div></details>

“[[Chosen Champion]]” and “[[Unit|unit]] in the [[Champion Zone]]” refer to a unit in the Champion Zone unless specified otherwise. ^cr-355-9-a-5

<details class="rule-ref"><summary title="Core rule 355.9.a.5 · PDF page 48" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.9.a.5 · PDF page 48</div></details>

It meets all [[Targeting|targeting]] restrictions. e.g., A [[Unit|unit]] is a valid target for a [[Spell|spell]] that refers to a “unit at a [[Battlefield|battlefield]],” “[[Enemy|enemy]] unit,” “unit you [[Control|control]],” or “unit with [[Might]] 4 or greater” only if it meets the appropriate criteria. e.g. A unit that reads “I can’t be chosen by enemy spells or [[Ability|abilities]].” is not a valid target for any enemy spell or ability, even if it meets other targeting restrictions. ^cr-355-9-b

<details class="rule-ref"><summary title="Core rule 355.9.b · PDF page 48" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.9.b · PDF page 48</div></details>

It is not the [[Spell|spell]] or [[Ability|ability]] itself. e.g., A spell that says “Counter a spell” cannot target itself. e.g., An ability of a [[Permanent|permanent]] can target that permanent, because abilities and their sources are separate objects. ^cr-355-9-c

<details class="rule-ref"><summary title="Core rule 355.9.c · PDF page 48" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.9.c · PDF page 48</div></details>

A [[Game Object|game object]], player, or [[Zone|zone]] mentioned in the text of a [[Spell|spell]], [[Activated Ability|activated ability]], or [[Triggered Ability|triggered ability]] is a target UNLESS any of the following are true: ^cr-355-10

<details class="rule-ref"><summary title="Core rule 355.10 · PDF page 48" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.10 · PDF page 48</div></details>

It is in a [[Zone|zone]] whose information status is not Public. e.g., “[[Ready]] a [[Legend|legend]]” targets a legend, because the [[Legend Zone]] is Public. e.g., “Return a [[Unit|unit]] from your [[Trash|trash]] to your [[Hand|hand]]” targets a unit [[Card|card]] in your trash, because your trash is Public. e.g., “You may [[Play|play]] a unit from your hand, ignoring its [[Costs|costs]]” does not target a unit card in your hand, because your hand is not a public zone. ^cr-355-10-a

<details class="rule-ref"><summary title="Core rule 355.10.a · PDF page 48" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.10.a · PDF page 48</div></details>

Public [[Zone|zones]] are [[Battlefield]] Zones, [[Base|Bases]], [[Trash|Trashes]], [[Legend]] Zones, [[Champion Zone|Champion Zones]], and [[Facedown Zone|Facedown Zones]]. ^cr-355-10-a-1

<details class="rule-ref"><summary title="Core rule 355.10.a.1 · PDF page 48" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.10.a.1 · PDF page 48</div></details>

It is included only as part of a [[Targeting|targeting]] restriction for another choice or only as a restriction or permission for a [[Game Action|game action]]. e.g., “[[Kill]] a [[Unit|unit]] at a [[Battlefield|battlefield]]” targets a unit, but not a battlefield, because the units are targets and “at a battlefield” is a restriction. e.g., “Kill all units at a battlefield” targets a battlefield, but not any units. e.g., “[[Play]] a unit from your [[Hand|hand]] to a battlefield” doesn’t target a battlefield. ^cr-355-10-b

<details class="rule-ref"><summary title="Core rule 355.10.b · PDF page 48" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.10.b · PDF page 48</div></details>

It is included only as part of a [[Costs|cost]], trigger condition, or [[Replacement Effect|replacement effect]]. e.g., “As an [[Additional Cost|additional cost]] to [[Play|play]] me, [[Kill|kill]] a [[Friendly|friendly]] [[Unit|unit]]” doesn’t target anything. e.g., “When a friendly unit dies, kill a [[Gear|gear]]” targets a gear, but not a friendly unit. e.g., “When you play me, the next time a friendly unit would die this [[Turn|turn]], return it to your [[Hand|hand]] instead” doesn’t target anything. The replacement effect applies when any friendly unit dies. e.g., “Choose a friendly unit. The next time it would die this turn, return it to your hand instead” targets a friendly unit, because “choose a friendly unit” is not part of the replacement effect. ^cr-355-10-c

<details class="rule-ref"><summary title="Core rule 355.10.c · PDF page 48-49" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.10.c · PDF page 48-49</div></details>

This includes [[Costs within Instructions|costs within instructions]], identified by phrases like “&#91;do X&#93; to &#91;do Y&#93;.” The [[Costs|cost]] within that instruction is “&#91;do X&#93;.” e.g., “When I [[Hold|hold]], you may [[Kill|kill]] another [[Friendly|friendly]] [[Unit|unit]] here to [[Draw|draw]] 1” does not target anything. e.g., “When you [[Play|play]] me, you may spend a [[Buffs|buff]] to [[Move|move]] a friendly unit” targets the friendly unit, but not the buff. ^cr-355-10-c-1

<details class="rule-ref"><summary title="Core rule 355.10.c.1 · PDF page 49" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.10.c.1 · PDF page 49</div></details>

It is programmatically selected based on its characteristics rather than chosen by the [[Spell|spell]] or [[Ability|ability]]’s controller. e.g., “[[Kill]] all [[Unit|units]] at a [[Battlefield|battlefield]]” targets a battlefield, but does not target any units. e.g., “Kill all units at battlefields” doesn’t target anything. e.g., “Kill a unit. Its controller draws 2” targets the unit, but not its controller. e.g., “[[Recycle]] all [[Card|cards]] in your [[Trash|trash]]” doesn’t target anything, because it affects all cards and you only have one trash. ^cr-355-10-d

<details class="rule-ref"><summary title="Core rule 355.10.d · PDF page 49" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.10.d · PDF page 49</div></details>

This exception applies solely to objects for which no choice is ever possible. ^cr-355-10-d-1

<details class="rule-ref"><summary title="Core rule 355.10.d.1 · PDF page 49" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.10.d.1 · PDF page 49</div></details>

This exception does not apply to objects that are the only valid choice at the moment a [[Spell|spell]] or [[Ability|ability]] is placed on the [[Chain|chain]], but which would require a choice under other circumstances. e.g., “[[Kill]] a [[Unit|unit]] at a [[Battlefield|battlefield]]” always targets a unit, even if that unit is the only unit currently at a battlefield. ^cr-355-10-d-2

<details class="rule-ref"><summary title="Core rule 355.10.d.2 · PDF page 49" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.10.d.2 · PDF page 49</div></details>

It is part of a set of objects chosen in whole or in part by other players. e.g., “Each player kills a [[Unit|unit]] they [[Control|control]]” does not target. Each player, including the one who played the [[Spell|spell]], chooses a unit to [[Kill|kill]] as the spell or [[Ability|ability]] resolves. ^cr-355-10-e

<details class="rule-ref"><summary title="Core rule 355.10.e · PDF page 49" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.10.e · PDF page 49</div></details>

It is identified in an instruction that a player “must” complete. e.g., “You must [[Recycle|recycle]] one of your [[Rune|runes]]” doesn’t target anything. You choose from among your runes as the [[Spell|spell]] or [[Ability|ability]] resolves. e.g., “Recycle a rune you [[Control|control]]” targets a rune. You choose a rune you control as you put the spell or ability on the [[Chain|chain]]. ^cr-355-10-f

<details class="rule-ref"><summary title="Core rule 355.10.f · PDF page 49" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.10.f · PDF page 49</div></details>

It is a [[Legend|legend]] “you” [[Control|control]]. e.g. “[[Ready]] your legend.” doesn’t target any legend. If a player controls multiple legends, they choose one as the [[Spell|spell]] or [[Ability|ability]] resolves. e.g. “Ready a [[Friendly|friendly]] legend.” targets the friendly legend. e.g. “[[Exhaust]] an [[Enemy|enemy]] legend.” targets the enemy legend. ^cr-355-10-g

<details class="rule-ref"><summary title="Core rule 355.10.g · PDF page 49" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.10.g · PDF page 49</div></details>

Some [[Card|cards]] identify a group of Targets with [[Targeting]] Requirements that must be met by the group as a whole. ^cr-355-11

<details class="rule-ref"><summary title="Core rule 355.11 · PDF page 49" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.11 · PDF page 49</div></details>

As they’re finalized on the [[Chain|chain]], such [[Card|cards]] can choose any group of valid targets that collectively fulfill the [[Targeting|targeting]] restriction. ^cr-355-11-a

<details class="rule-ref"><summary title="Core rule 355.11.a · PDF page 49" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.11.a · PDF page 49</div></details>

If the group of targets no longer collectively fulfill the [[Targeting|targeting]] restriction as the [[Spell|spell]] or [[Ability|ability]] resolves, that spell or ability’s controller must choose a legal subset of the original targets that fulfills the targeting requirement for the spell or ability to affect. ^cr-355-11-b

**Example:** A player plays Fox-Fire, a [[Spell|spell]] that says in part “[[Kill]] any number of [[Unit|units]] at a [[Battlefield|battlefield]] with total [[Might]] 4 or less.” That player chooses four 1 &#91;M&#93; Recruit [[Token|tokens]] at a single battlefield. As a Reaction, another player gives two of those Recruits +1 &#91;M&#93;, so the Recruits’ Mights are 1, 1, 2, and 2. Then Fox-Fire resolves. The Recruits no longer have total Might 4 or less, so Fox-Fire’s controller must choose a legal subset of the original targets to affect. They could choose to kill the two 2 &#91;M&#93; Recruits, or the two 1 &#91;M&#93; Recruits plus one 2 &#91;M&#93; Recruit. The units they choose are Fox-Fire’s remaining legal targets. They can’t choose to affect units at the same battlefield that weren’t initially chosen as targets. They can, however, choose to affect units that were initially chosen as targets that left the chosen battlefield before Fox-Fire resolved as long as those units are all located at the same battlefield.

<details class="rule-ref"><summary title="Core rule 355.11.b · PDF page 50" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.11.b · PDF page 50</div></details>

Any legal subset must include the maximum number of legal targets possible for that subset. ^cr-355-11-b-1

**Example:** A player plays Bellow’s Breath, a [[Spell|spell]] that reads in part “[[Deal]] 1 to up to 3 [[Unit|units]] at the same [[Location|location]].” They choose 3 units at the same [[Battlefield|battlefield]]. In reaction to Bellow’s Breath, the controller of those units plays Flash, [[Movement|moving]] two of them to [[Base|base]]. On resolution of Bellow’s Breath, Bellow’s Breath’s controller cannot choose one unit in base and not the other. They may choose either of the legal subsets; the one unit remaining at the battlefield, or the two units in base.

<details class="rule-ref"><summary title="Core rule 355.11.b.1 · PDF page 50" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.11.b.1 · PDF page 50</div></details>

If a [[Spell|spell]] specifies that a player may perform a [[Game Action]] on some number of [[Game Object|Game Objects]], then all choices are considered targeted and chosen independently of the decision to perform the Game Action. ^cr-355-12

<details class="rule-ref"><summary title="Core rule 355.12 · PDF page 50" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.12 · PDF page 50</div></details>

If a [[Card|card]] specifies that a player chooses “any number” or “up to” some number of [[Game Object|Game Objects]] to be affected, they may choose any number of available targets, including zero. If they choose zero, the [[Spell|spell]] or [[Ability|ability]] can be played without any targets. ^cr-355-13

<details class="rule-ref"><summary title="Core rule 355.13 · PDF page 50" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.13 · PDF page 50</div></details>

### Splitting

^cr-355-14

<details class="rule-ref"><summary title="Core rule 355.14 · PDF page 50" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.14 · PDF page 50</div></details>

If a [[Card|card]] specifies that an amount of [[Damage|damage]] may be split among some number of [[Unit|Units]], then each Unit chosen is Targeted. ^cr-355-14-a

<details class="rule-ref"><summary title="Core rule 355.14.a · PDF page 50" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.14.a · PDF page 50</div></details>

The Targets are chosen when the [[Spell|spell]] or [[Ability|ability]] is finalized on the [[Chain|chain]]. ^cr-355-14-b

<details class="rule-ref"><summary title="Core rule 355.14.b · PDF page 50" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.14.b · PDF page 50</div></details>

A number of Targets can only be chosen up to, and not exceeding, the initial amount of [[Damage|damage]] available when the [[Spell|spell]] is played. ^cr-355-14-c

**Example:** A player playing a [[Spell|spell]] that instructs them to "Split 5 [[Damage|damage]]" may only choose up to 5 [[Unit|units]], but may choose fewer.

<details class="rule-ref"><summary title="Core rule 355.14.c · PDF page 50" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.14.c · PDF page 50</div></details>

Each Target is valid, and contributes to [[Targeting Effect|Targeting Effects]] individually. ^cr-355-14-d

<details class="rule-ref"><summary title="Core rule 355.14.d · PDF page 50" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.14.d · PDF page 50</div></details>

The choice of how much [[Damage|damage]] is divided across the split is not decided until the resolution of the [[Spell|spell]] or [[Ability|ability]]. ^cr-355-14-e

<details class="rule-ref"><summary title="Core rule 355.14.e · PDF page 50" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.14.e · PDF page 50</div></details>

Each Target must receive a valid amount of [[Damage|damage]]. ^cr-355-14-f

<details class="rule-ref"><summary title="Core rule 355.14.f · PDF page 50" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.14.f · PDF page 50</div></details>

Valid [[Damage|damage]] is a positive integer amount, greater than or equal to 1 damage. ^cr-355-14-g

See [[Deal#^cr-418|Deal]] for more information.

<details class="rule-ref"><summary title="Core rule 355.14.g · PDF page 50" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.14.g · PDF page 50</div></details>

If, at resolution of the [[Spell|spell]] or effect, there are more Targets than available [[Damage|damage]] to divide, then the player who controls the effect dealing damage determines which Targets cease being Targets. ^cr-355-14-h

<details class="rule-ref"><summary title="Core rule 355.14.h · PDF page 51" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.14.h · PDF page 51</div></details>

That player cannot choose to have fewer Targets than they have [[Damage|damage]] to split when choosing which Targets cease being Targets. ^cr-355-14-h-1

**Example:** A player plays Alpha Strike, which reads in part “Choose a [[Friendly|friendly]] [[Unit|unit]]. It deals [[Damage|damage]] equal to its [[Might]] split among [[Enemy|enemy]] units at [[Battlefield|battlefields]].” They target their 5 &#91;M&#93; unit and five 1 &#91;M&#93; enemy Recruits at battlefields. In reaction, their opponent plays Feral Strength [[Targeting|targeting]] one of their recruits, and Frigid Touch targeting the 5 &#91;M&#93; unit. When Alpha Strike resolves, they have 3 damage to split, and must choose which targets cease being targets. They can’t choose for 4 of the units to cease being targets so that they can [[Deal|deal]] 3 to the 3 &#91;M&#93; recruit. They can only choose at most 2 of the targets to cease being targets.

<details class="rule-ref"><summary title="Core rule 355.14.h.1 · PDF page 51" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.14.h.1 · PDF page 51</div></details>

Any [[Costs|costs]] that were paid, or effects that were triggered as a result of those [[Game Object|Game Objects]] being chosen as Targets remain in effect, paid, or otherwise triggered. ^cr-355-14-i

<details class="rule-ref"><summary title="Core rule 355.14.i · PDF page 51" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.14.i · PDF page 51</div></details>

These choices cannot be changed after this step unless instructed to by a [[Spell|spell]] or [[Ability|ability]]. ^cr-355-15

See [[Making New Choices#^cr-750|Making New Choices]] for more information.

<details class="rule-ref"><summary title="Core rule 355.15 · PDF page 51" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.15 · PDF page 51</div></details>

A player may not make choices during this step that will deterministically result in illegal choices or actions later in this process unless they have no choice. ^cr-355-16

**Example:** A player plays a [[Card|card]] which reads “As an [[Additional Cost|additional cost]] to [[Play|play]] this, [[Kill|kill]] the [[Unit|unit]] you [[Control|control]] with the most [[Might]]. Give a [[Friendly|friendly]] unit +&#91;M&#93; equal to the killed unit’s Might this [[Turn|turn]]. [[Predict]] 2.” They cannot choose to target their unit with the highest Might during this step of finalization.

<details class="rule-ref"><summary title="Core rule 355.16 · PDF page 51" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.16 · PDF page 51</div></details>

If a [[Game Effect]] has introduced a mandatory requirement on any of these choices, that mandatory requirement must be followed if possible. A mandatory requirement is one that specifies what choice can be made or how that choice is made, but doesn't specifically disallow other game states. ^cr-355-17

**Example:** Here to Help is a [[Spell|spell]] that reads in part “You may [[Play|play]] a [[Unit|unit]] from your [[Hand|hand]] to a [[Battlefield|battlefield]] you [[Control|control]].” If its controller decides to play a unit, they must play it to a battlefield they control.

**Example:** Rek’Sai, Swarm Queen is a [[Unit|unit]] that reads “When I attack, you may [[Reveal|reveal]] the top 2 [[Card|cards]] of your [[Main Deck]]. You may [[Banish|banish]] one, then [[Play|play]] it. If it is a unit, you may play it here. [[Recycle]] the rest.” The “you may play it here,” portion of this [[Ability|ability]] is not a mandatory requirement, because the player isn’t required to play the unit to that [[Location|location]].

<details class="rule-ref"><summary title="Core rule 355.17 · PDF page 51" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.17 · PDF page 51</div></details>

If there are multiple mandatory requirements that do not conflict, players must make a choice that will satisfy those mandatory requirements. Any individual group of such complementary mandatory requirements that contains as many non-contradictory mandatory requirements as possible forms a set. If there are two or more sets of mandatory requirements that are mutually contradictory, choose one of those sets and ignore the rest. ^cr-355-17-a

**Example:** Here to Help is played from facedown at Targon’s Peak. Its controller chooses to [[Play|play]] a Dune Drake from [[Hand|hand]]. The other [[Battlefield|battlefield]] is Dragon Roost. When finalizing Dune Drake, they choose to pay the &#91;A&#93;&#91;A&#93; [[Additional Cost|additional cost]] from Dragon Roost. There are two competing mandatory requirements here: playing Dune Drake to Targon’s Peak, or playing it to Dragon Roost. Dune Drake’s controller must choose one of those requirements to satisfy, and ignore the rest.

**Example:** If Here to Help were played from [[Hand|hand]], and its controller controlled both [[Battlefield|battlefields]], if they paid the &#91;A&#93;&#91;A&#93; [[Additional Cost|additional cost]], they would have no choice but to [[Play|play]] Dune Drake to Dragon Roost as it would satisfy both mandatory requirements.

<details class="rule-ref"><summary title="Core rule 355.17.a · PDF page 51" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.17.a · PDF page 51</div></details>

If there are one or more restrictions on choices being made during this process, those restrictions must be followed. Failure to do so means the [[Card|card]] will fail to finalize. ^cr-355-17-b

**Example:** Perched Grimwyrm is a [[Unit|unit]] that reads “[[Play]] me only to a [[Battlefield|battlefield]] you conquered this [[Turn|turn]].” If a player plays Perched Grimwyrm via Here to Help and they haven’t conquered a battlefield this turn, Perched Grimwyrm will fail to finalize. Although Here to Help presents a mandatory requirement, Perched Grimwyrm’s restriction on being played overrides it.

**Example:** Mageseeker Warden is a [[Unit|unit]] that reads in part “While I'm at a [[Battlefield|battlefield]], opponents can only [[Play|play]] units to their [[Base|base]].” If a player attempts to play a Perched Grimwyrm to a battlefield they’ve conquered this [[Turn|turn]] while their opponent controls a Mageseeker Warden at a battlefield, the Perched Grimwyrm will fail to finalize.

<details class="rule-ref"><summary title="Core rule 355.17.b · PDF page 51-52" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 355.17.b · PDF page 51-52</div></details>

If a [[Spell|spell]] or [[Ability|ability]] requires one or more players to make choices that are not outlined in this section, they are made on resolution. ^cr-355-18

<details class="rule-ref"><summary title="Core rule 356.1 · PDF page 52" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.1 · PDF page 52</div></details>

If an [[Ability|ability]] or instruction allows you to [[Play|play]] a [[Card|card]] “for &#91;[[Costs|Cost]]&#93;”, replace the card’s [[Base]] Costs with &#91;Cost&#93;. ^cr-356-1-a

<details class="rule-ref"><summary title="Core rule 356.1.a · PDF page 52" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.1.a · PDF page 52</div></details>

If an [[Ability|ability]] or instruction allows you to "ignore" one or more of a [[Card|card]]'s [[Costs|costs]], set the appropriate [[Base Cost]](s) of the card to zero. ^cr-356-1-b

<details class="rule-ref"><summary title="Core rule 356.1.b · PDF page 52" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.1.b · PDF page 52</div></details>

If a [[Card|card]] allows a player to [[Play|play]] a card "ignoring its [[Costs|cost]]," its [[Base|base]] [[Energy Cost|Energy cost]] and base [[Power Cost|Power cost]] are set to zero. ^cr-356-1-b-1

<details class="rule-ref"><summary title="Core rule 356.1.b.1 · PDF page 52" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.1.b.1 · PDF page 52</div></details>

If a [[Card|card]] instructs a player to [[Play|play]] a card "ignoring its [[Energy Cost|Energy cost]]" or "ignoring its [[Power Cost|Power cost]]," only the appropriate [[Costs|cost]] is set to zero, and the remaining cost still applies. ^cr-356-1-b-2

<details class="rule-ref"><summary title="Core rule 356.1.b.2 · PDF page 52" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.1.b.2 · PDF page 52</div></details>

Further additional [[Costs|costs]] and/or cost increases applied in subsequent steps may raise the [[Card|card]]'s Total Cost above zero. ^cr-356-1-b-3

**Example:** [[Legion]] Rearguard is a Fury [[Unit|unit]] that [[Costs|costs]] 2 [[Energy]] and 0 [[Power]] and has [[Accelerate]]. A player plays Legion Rearguard and is instructed to ignore its costs, but chooses to pay the Accelerate cost. They ignore Legion Rearguard's [[Base Cost]] of 2 Energy, but the optional [[Additional Cost|additional cost]] of 1 Energy and 1 Fury Power is added to its Total Cost and must be paid.

<details class="rule-ref"><summary title="Core rule 356.1.b.3 · PDF page 52" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.1.b.3 · PDF page 52</div></details>

Effects that refer to the [[Base Cost]] of the [[Card|card]] refer to the Printed or Copied Base Cost of said card, and not the modified Base Cost that is used when determining the total [[Costs|cost]] of the card. ^cr-356-1-c

<details class="rule-ref"><summary title="Core rule 356.1.c · PDF page 52" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.1.c · PDF page 52</div></details>

### Optional Additional Costs

^cr-356-2-b

<details class="rule-ref"><summary title="Core rule 356.2.b · PDF page 53" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.2.b · PDF page 53</div></details>

Some Optional [[Costs]] specified by [[Passive Ability|Passive Abilities]] on the [[Card|card]] being played or another card are Non-Mandatory, and must be paid only if the player made the choice to pay them in step 2. They use the phrase "as an [[Additional Cost|additional cost]]" and the word "may." ^cr-356-2-b-1

**Example:** A [[Unit|unit]] has the [[Ability|ability]] "As you [[Play|play]] me, you may [[Discard|discard]] 1 as an [[Additional Cost|additional cost]]. If you do, reduce my [[Costs|cost]] by &#91;2&#93;." While playing the unit, its controller declares their intention to pay the additional cost in step 2, applies that additional cost in [[Process of Playing a Card#^cr-356-2|Process of Playing a Card]], applies the discount granted by paying that cost in [[Process of Playing a Card#^cr-356-4|Process of Playing a Card]], and discards a [[Card|card]] to pay that additional cost in [[Process of Playing a Card#^cr-357-2|Process of Playing a Card]].

See [[Passive Ability#^cr-363|Passive Abilities]] for more information.

<details class="rule-ref"><summary title="Core rule 356.2.b.1 · PDF page 53" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.2.b.1 · PDF page 53</div></details>

Apply [[Costs|cost]] increases. ^cr-356-3

<details class="rule-ref"><summary title="Core rule 356.3 · PDF page 53" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.3 · PDF page 53</div></details>

Apply discounts. ^cr-356-4

<details class="rule-ref"><summary title="Core rule 356.4 · PDF page 53" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.4 · PDF page 53</div></details>

Discounts may be applied by the [[Card|card]] being played or by any other card or effect. ^cr-356-4-a

<details class="rule-ref"><summary title="Core rule 356.4.a · PDF page 53" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.4.a · PDF page 53</div></details>

Discounts may say that [[Card|cards]] "[[Costs|cost]] &#91;amount&#93; less" or that one or more of their costs are "reduced by &#91;amount&#93;." ^cr-356-4-b

<details class="rule-ref"><summary title="Core rule 356.4.b · PDF page 53" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.4.b · PDF page 53</div></details>

Discounts that only apply to a component of the [[Costs|cost]] will be applied when that component is added to the cost of the [[Spell|spell]] and before any other discounts. ^cr-356-4-c

**Example:** Ezreal, Prodigy reads “[[Optional Additional Costs|optional additional costs]] you pay [[Costs|cost]] &#91;1&#93; or &#91;A&#93; less.” When playing a Frigid Touch and choosing to pay the [[Additional Cost|additional cost]] in step 2, as soon as the additional cost is added to the cost of the [[Spell|spell]], Ezreal, Prodigy’s discount is applied to it.

<details class="rule-ref"><summary title="Core rule 356.4.c · PDF page 53" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.4.c · PDF page 53</div></details>

Discounts that apply to a given component of a [[Spell|spell]]’s [[Costs|cost]] may be applied in any order to that component, and apply only to that component. ^cr-356-4-c-1

<details class="rule-ref"><summary title="Core rule 356.4.c.1 · PDF page 53" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.4.c.1 · PDF page 53</div></details>

Discounts that apply to a given component of a [[Spell|spell]]’s [[Costs|cost]] cannot reduce that component to less than 0. ^cr-356-4-c-2

<details class="rule-ref"><summary title="Core rule 356.4.c.2 · PDF page 53" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.4.c.2 · PDF page 53</div></details>

Discounts that apply to the total [[Costs|cost]] of a [[Spell|spell]] and not any one component of the cost must be applied after any discount that applies only to a component of the cost. ^cr-356-4-d

<details class="rule-ref"><summary title="Core rule 356.4.d · PDF page 53" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.4.d · PDF page 53</div></details>

These discounts may be applied in any order as long as they are applied after component discounts. ^cr-356-4-d-1

<details class="rule-ref"><summary title="Core rule 356.4.d.1 · PDF page 53" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.4.d.1 · PDF page 53</div></details>

If a discount applies a minimum [[Costs|cost]], that minimum applies only to that discount. ^cr-356-4-e

**Example:** Eager Apprentice says "While I'm at a [[Battlefield|battlefield]], the [[Energy]] [[Costs|costs]] for [[Spell|spells]] you [[Play|play]] is reduced by &#91;1&#93;, to a minimum of &#91;1&#93;." A player who controls Eager Apprentice and a [[Unit|unit]] with 7 [[Might]] plays Sky Splitter, a spell that costs 8 Energy and says "This spell's [[Energy Cost|Energy cost]] is reduced by the highest Might among units you [[Control|control]]." That player can choose to apply Eager Apprentice's discount first, reducing Sky Splitter's Energy cost to 7, then apply Sky Splitter's discount, reducing its Energy cost to 0. If they applied these discounts in the other order, Sky Splitter's Energy cost would be 1.

<details class="rule-ref"><summary title="Core rule 356.4.e · PDF page 53" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.4.e · PDF page 53</div></details>

Discounts can reduce additional [[Costs|costs]], including to 0. ^cr-356-4-f

<details class="rule-ref"><summary title="Core rule 356.4.f · PDF page 53" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.4.f · PDF page 53</div></details>

An optional [[Additional Cost|additional cost]] was "paid" if the player made the decision to pay it. It doesn't matter how much the player actually paid. ^cr-356-4-f-1

**Example:** Clockwork Keeper is a [[Unit|unit]] that [[Costs|costs]] 2 [[Energy]] and 0 [[Power]] and says "As you [[Play|play]] me, you may pay &#91;C&#93; as an [[Additional Cost|additional cost]]. If you do, [[Draw|draw]] 1." A player controls a [[Card|card]] that says "Units you play cost &#91;A&#93; less." That player plays Clockwork Keeper and chooses to pay the optional additional cost of &#91;C&#93;. They will draw a card, even though the optional additional cost was reduced to 0.

<details class="rule-ref"><summary title="Core rule 356.4.f.1 · PDF page 54" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.4.f.1 · PDF page 54</div></details>

If a discount applies a variable [[Costs|cost]] reduction to the [[Card|card]], that value is checked now. ^cr-356-4-g

**Example:** Rhasa, the Sunderer reads “I [[Costs|cost]] &#91;1&#93; less for each [[Card|card]] in your [[Trash|trash]].” The value of this discount depends on the number of cards in the trash. That value is checked during this step when the discount is applied to Rhasa’s cost. If the number of cards in his controller’s trash changes at a later point in the finalization process, that will not affect the value checked during this step or the total cost calculated in this step.

<details class="rule-ref"><summary title="Core rule 356.4.g · PDF page 54" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.4.g · PDF page 54</div></details>

Apply modifications to the total [[Costs|cost]] in any order. ^cr-356-5

<details class="rule-ref"><summary title="Core rule 356.5 · PDF page 54" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.5 · PDF page 54</div></details>

If an effect allows a player to [[Play|play]] a [[Card|card]] ignoring “any and all [[Costs|costs]],” set the total cost to &#91;0&#93;, including any non-standard costs. ^cr-356-5-a

<details class="rule-ref"><summary title="Core rule 356.5.a · PDF page 54" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.5.a · PDF page 54</div></details>

[[Energy]] and [[Power]] [[Costs|costs]] can't be reduced below 0. ^cr-356-6

<details class="rule-ref"><summary title="Core rule 356.6 · PDF page 54" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 356.6 · PDF page 54</div></details>

[[Costs]] may be [[Energy]] costs, [[Power]] costs, or non-standard costs. ^cr-356-7

**Example:** A [[Card|card]] reads "As an [[Additional Cost|additional cost]] to [[Play|play]] me, [[Kill|kill]] a [[Friendly|friendly]] [[Unit|unit]]." Killing a friendly unit is an additional cost to play that card.

4. Pay the [[Card|card]]'s [[Costs|costs]]. ^cr-357

<details class="rule-ref"><summary title="Core rule 357 · PDF page 54" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 357 · PDF page 54</div></details>

In total, pay the combined [[Energy Cost|Energy cost]] (if any) and [[Power Cost|Power cost]] (if any). ^cr-357-1

<details class="rule-ref"><summary title="Core rule 357.1 · PDF page 54" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 357.1 · PDF page 54</div></details>

During this step, the [[Card|card]]'s controller can use [[Activated Ability|activated abilities]] with the Reaction [[Tag|tag]] that Add resources to add [[Energy]] and [[Power]] to pay the card's [[Costs|costs]]. ^cr-357-1-a

See [[Rune Pool#^cr-165|Rune Pools]] and [[Add#^cr-430|Add]] for more information.

<details class="rule-ref"><summary title="Core rule 357.1.a · PDF page 54" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 357.1.a · PDF page 54</div></details>

In addition, pay any non-standard [[Costs|Cost]] summed in step 3 in any order. ^cr-357-2

**Example:** A [[Card|card]] reads in part “As an [[Additional Cost|additional cost]] to [[Play|play]] me, [[Kill|kill]] a [[Friendly|friendly]] [[Unit|unit]] and [[Discard|discard]] a unit.” When paying the [[Costs|costs]] for that card, its controller can pay those two costs in any order; they can kill a friendly unit first and then discard a unit, or they can discard a unit and then kill a friendly unit.

<details class="rule-ref"><summary title="Core rule 357.2 · PDF page 54" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 357.2 · PDF page 54</div></details>

[[Costs]] that are replaced with other events by [[Replacement Effect|replacement effects]] are still considered paid. ^cr-357-2-a

**Example:** A player plays Cruel Patron, which says "As an [[Additional Cost|additional cost]] to [[Play|play]] me, [[Kill|kill]] a [[Friendly|friendly]] [[Unit|unit]]." They also [[Control|control]] Zhonya’s Hourglass, which says “If a friendly unit would die, kill this instead. [[Heal]] that unit, [[Exhaust|exhaust]] it, and recall it.” They choose to kill a friendly unit during step 3, but as they pay the [[Costs|cost]] in step 4, Zhonya’s Hourglass replaces that unit’s death. The cost is considered paid, and the player can continue playing Cruel Patron.

<details class="rule-ref"><summary title="Core rule 357.2.a · PDF page 54" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 357.2.a · PDF page 54</div></details>

A player may not pay [[Costs|costs]] during this step that will deterministically result in illegal choices or actions later in this process unless they have no choice. ^cr-357-3

**Example:** A player plays a [[Card|card]] which reads “as an [[Additional Cost|additional cost]] to [[Play|play]] this, you may [[Kill|kill]] a [[Friendly|friendly]] [[Unit|unit]]. Give a friendly unit +2 &#91;M&#93; this [[Turn|turn]]. If you paid the [[Costs|cost]], give that unit +7 &#91;M&#93; this turn instead” If they chose to pay the cost, they must choose to kill a unit other than the targeted unit unless they have no choice.

<details class="rule-ref"><summary title="Core rule 357.3 · PDF page 54" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 357.3 · PDF page 54</div></details>

5. Check legality. ^cr-358

<details class="rule-ref"><summary title="Core rule 358 · PDF page 54" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 358 · PDF page 54</div></details>

Check that the [[Card|card]] made appropriate choices. ^cr-358-1

**Example:** If the [[Card|card]] chose targets, ensure that the targets are legal.

**Example:** If the [[Card|card]] made choices that had restrictions or requirements, ensure that restrictions were followed and that the requirements were met as appropriate.

See [[Process of Playing a Card#^cr-355|Make Relevant Choices]] for more information.

<details class="rule-ref"><summary title="Core rule 358.1 · PDF page 55" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 358.1 · PDF page 55</div></details>

Check that all [[Costs|costs]] were paid. ^cr-358-2

<details class="rule-ref"><summary title="Core rule 358.2 · PDF page 55" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 358.2 · PDF page 55</div></details>

Check that the outcome of the effect of this [[Card|card]] being played would not create an illegal state. ^cr-358-3

**Example:** Check that a [[Spell|spell]]'s execution does not create a state where a [[Battlefield]] has [[Unit|Units]] controlled by 3 different players.

**Example:** Check that a [[Permanent|permanent]] is not played to a [[Base|base]] other than that of its controller.

<details class="rule-ref"><summary title="Core rule 358.3 · PDF page 55" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 358.3 · PDF page 55</div></details>

If a [[Game Effect]] prevents the performance of a [[Game Action|game action]], that effect doesn’t [[Prevent|prevent]] [[Card|cards]] and [[Ability|abilities]] that instruct a player to perform that game action from being played or finalized. ^cr-358-3-a

**Example:** Flash is a [[Spell|spell]] that reads in part “[[Move]] up to 2 [[Friendly|friendly]] [[Unit|units]] to [[Base|base]].” Vilemaw’s Lair is a [[Battlefield|battlefield]] that reads “Units can’t move from here to base.” Flash is legal to [[Play|play]] choosing a unit at Vilemaw’s Lair; on resolution of the spell, the move instruction will be negated.

<details class="rule-ref"><summary title="Core rule 358.3.a · PDF page 55" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 358.3.a · PDF page 55</div></details>

This check only extends to the resolution of the current [[Card|card]]. Any [[Reflexive Trigger|Reflexive Triggers]], cards played, or [[Ability|abilities]] triggered as a result of the execution must be evaluated on their own merits as they finalize. ^cr-358-3-b

<details class="rule-ref"><summary title="Core rule 358.3.b · PDF page 55" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 358.3.b · PDF page 55</div></details>

Check that the [[Card|card]] has the appropriate permissions to be played at this timing. ^cr-358-4

**Example:** If the state is [[Showdowns|Showdown]] Closed and the [[Card|card]] was the one that Closed the state, ensure that it has &#91;[[Action (Keyword)|Action]]&#93; or &#91;[[Reaction (Keyword)|Reaction]]&#93;.

**Example:** If the state is Closed and the [[Card|card]] wasn’t the one that Closed the state, ensure that it has &#91;[[Reaction (Keyword)|Reaction]]&#93;.

<details class="rule-ref"><summary title="Core rule 358.4 · PDF page 55" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 358.4 · PDF page 55</div></details>

### Handling illegal and impossible instructions

^cr-359-3-e

<details class="rule-ref"><summary title="Core rule 359.3.e · PDF page 56" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e · PDF page 56</div></details>

The [[Spell|spell]] resolves even if some or all of its targets are illegal. ^cr-359-3-e-1

<details class="rule-ref"><summary title="Core rule 359.3.e.1 · PDF page 56" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.1 · PDF page 56</div></details>

A target is illegal as the [[Spell|spell]] resolves if it no longer meets the [[Targeting|targeting]] requirements of the spell, or if it has changed [[Zone|Zones]] to or from a Non-Board Zone. ^cr-359-3-e-2

<details class="rule-ref"><summary title="Core rule 359.3.e.2 · PDF page 56" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.2 · PDF page 56</div></details>

This includes [[Targeting|targeting]] restrictions that are applied to the [[Spell|spell]] by [[Game Effect|game effects]] other than the spell’s [[Instructions|instructions]] themselves. ^cr-359-3-e-2-a

**Example:** Temporal Breach is a [[Spell|spell]] that reads in part “[[Banish]] a [[Unit|unit]], then its owner plays it to the same [[Location|location]], ignoring its [[Costs|cost]].” By default, the only [[Targeting|targeting]] restrictions on the spell are that the target is a unit, and that the unit is able to be chosen by the spell. However, if Temporal Breach is played from facedown, it gains the restriction that it must choose from among [[Game Object|game objects]] at the [[Battlefield|battlefield]] it was played from. If the unit it chooses moves to a different location, that unit will be an illegal target on resolution of Temporal Breach.

<details class="rule-ref"><summary title="Core rule 359.3.e.2.a · PDF page 56" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.2.a · PDF page 56</div></details>

If a target ceases to meet the [[Targeting|targeting]] requirements while the [[Spell|spell]] is on the [[Chain|chain]], then meets them again, it's a legal target. ^cr-359-3-e-3

**Example:** A [[Spell|spell]] targets "a [[Unit|unit]] at a [[Battlefield|battlefield]]." A player reacts with a spell that moves the unit to [[Base|base]], then another player reacts with a spell that moves it back to that battlefield, then the original spell resolves. The unit is a legal target.

<details class="rule-ref"><summary title="Core rule 359.3.e.3 · PDF page 56" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.3 · PDF page 56</div></details>

If a target changes [[Zone|Zones]] to or from a Non-Board Zone and then returns to its original zone, it is no longer a legal target, because it's not treated as the same object. ^cr-359-3-e-4

Examples: An [[Enemy|enemy]] [[Unit|unit]] at a [[Battlefield|battlefield]] is no longer a legal target if it is no longer an enemy, no longer a unit, or no longer at a battlefield. A unit with 3 or less [[Might]] is no longer a legal target if it is no longer a unit or if its Might is greater than 3. Something that's [[Exhaust|exhausted]] is no longer a legal target if it is no longer exhausted. (It can't stop being "something.")

<details class="rule-ref"><summary title="Core rule 359.3.e.4 · PDF page 56" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.4 · PDF page 56</div></details>

If any of the [[Spell|spell]]'s targets are no longer legal, those [[Game Object|game objects]], players, or [[Zone|zones]] are unaffected by the spell as it resolves. Any [[Instructions|instructions]] related to an illegal target can’t be followed. ^cr-359-3-e-5

**Example:** A player plays Void Seeker, a [[Spell|spell]] that says "[[Deal]] 4 to a [[Unit|unit]] at a [[Battlefield|battlefield]]. [[Draw]] 1." The unit's controller uses a Reaction to [[Move|move]] the unit to their [[Base|base]]. Since the unit is no longer a legal target, it is not dealt any [[Damage|damage]]. Void Seeker's controller still draws 1.

**Example:** A player plays Bellow’s Breath [[Targeting|targeting]] a [[Unit|unit]] [[In Combat|in combat]] that reads in part “I can’t be chosen by [[Enemy|enemy]] [[Spell|spells]] and [[Ability|abilities]] unless I’m in combat.” In reaction, that unit’s controller plays Flash, [[Movement|moving]] the unit to their [[Base|base]]. The unit is no longer in combat, so it is no longer a legal target for Bellow’s Breath. The unit will be unaffected by Bellow’s Breath as it resolves.

**Example:** A player plays [[Hidden]] Blade from the [[Facedown Zone|facedown zone]] at a [[Battlefield|battlefield]], [[Targeting|targeting]] an [[Enemy|enemy]] [[Unit|unit]]. In reaction to Hidden Blade, their opponent plays Tideturner from facedown at another battlefield, choosing to [[Swap|swap]] [[Location|locations]] with the unit Hidden Blade targeted. When Hidden Blade resolves, the chosen unit is no longer at the appropriate battlefield, so any [[Instructions|instructions]] related to that unit are ignored.

<details class="rule-ref"><summary title="Core rule 359.3.e.5 · PDF page 56-57" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.5 · PDF page 56-57</div></details>

[[Instructions]] that can't be followed because of illegal targets, or because they reference information that is unavailable, are considered Ignored. Instructions that can’t be followed for any other reason are Negated. ^cr-359-3-e-6

**Example:** A player plays Ride the Wind choosing to [[Move|move]] their [[Unit|unit]] at Vilemaw’s Lair to [[Base|base]]. Base is a legal move destination for Ride the Wind, but on resolution of Ride the Wind’s effect, the move instruction will be negated because Vilemaw’s restriction makes the instruction impossible.

**Example:** A player plays [[Hidden]] Blade [[Targeting|targeting]] a [[Unit|unit]] at a [[Battlefield|battlefield]]. In reaction to Hidden Blade, the unit’s controller plays Flash, [[Movement|moving]] it to [[Base|base]]. Hidden Blade’s instruction “[[Kill]] a unit.” will be ignored on resolution of the [[Spell|spell]].

<details class="rule-ref"><summary title="Core rule 359.3.e.6 · PDF page 57" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.6 · PDF page 57</div></details>

If all of an instruction's Targets become Invalid or Unavailable by the time the [[Spell|spell]] begins resolving, that instruction will not execute. ^cr-359-3-e-7

<details class="rule-ref"><summary title="Core rule 359.3.e.7 · PDF page 57" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.7 · PDF page 57</div></details>

If an instruction has more than one Target and fewer than all of the Targets become Invalid or Unavailable by the time the [[Spell|spell]] begins resolving, the instruction will execute, with only the Targets available and valid being operated on. ^cr-359-3-e-8

**Example:** Singularity reads “[[Deal|deal]] 6 to each of up to two [[Unit|units]].” The instruction will execute even if one of those units is made unavailable before the [[Spell|spell]] begins.

<details class="rule-ref"><summary title="Core rule 359.3.e.8 · PDF page 57" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.8 · PDF page 57</div></details>

The process for a [[Card|card]]'s choice becoming Invalid or Unavailable is referred to as Mistargeting. ^cr-359-3-e-9

**Example:** A [[Spell|spell]] has the instruction "[[Deal]] 2 to a [[Unit|unit]] at a [[Battlefield|battlefield]]." Before that instruction can execute, the chosen unit is moved to its [[Base|base]]. The instruction will not be executed, because it specifies that the unit it chooses must be at a Battlefield, and by the time it attempted to execute, the unit was no longer valid as a choice.

<details class="rule-ref"><summary title="Core rule 359.3.e.9 · PDF page 57" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.9 · PDF page 57</div></details>

If another [[Spell|spell]] or [[Ability|ability]] attempts to reference the number of [[Game Object|game objects]], players, or [[Zone|zones]] that a [[Finalized Chain Item]] targets, it will include any mistargeted choices in the zone specified implicitly or explicitly by the instruction that targeted them, but not any targets that have changed to or from a non-board zone. ^cr-359-3-e-9-a

**Example:** When a player moves their Volibear, Furious to an occupied [[Enemy|enemy]] [[Battlefield|battlefield]] and [[Combat|combat]] initiates, Volibear’s [[Attack Trigger|attack trigger]] goes on the [[Chain|chain]] [[Targeting|targeting]] three of the [[Unit|units]] at that battlefield. In reaction, the [[Defender|defending]] player plays Flash [[Movement|moving]] two of the three units back. That player cannot then target the attack trigger with Repulse, which reads “Choose a [[Friendly|friendly]] unit at a battlefield. Counter an enemy [[Spell|spell]] or [[Ability|ability]] that chooses it and no other friendly unit.” If the defending player instead played Heedless Resurrection twice, [[Kill|killing]] the two units, Repulse can legally target the attack trigger, because two of the targets have changed to a non-board [[Zone|zone]].

<details class="rule-ref"><summary title="Core rule 359.3.e.9.a · PDF page 57-58" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.9.a · PDF page 57-58</div></details>

It is possible for none of a [[Spell|spell]]'s [[Instructions|instructions]] to be executed as it resolves, due to all of them requiring targets to act on and all of those targets becoming Invalid or Unavailable. In this case, the spell has no effect but is still considered played. ^cr-359-3-e-10

**Example:** A player plays a [[Spell|spell]] that reads "[[Deal]] 2 to a [[Unit|unit]] at a [[Battlefield|battlefield]]" with no other [[Instructions|instructions]], and chooses an [[Enemy|enemy]] unit at a battlefield. They also [[Control|control]] a unit with the [[Ability|ability]] "When you [[Play|play]] a spell, give me +1 &#91;M&#93; this [[Turn|turn]]." Before the spell resolves, the chosen unit is moved to its [[Base|base]]. The spell resolves and its only instruction cannot be executed, but the unit's ability still triggers as the spell resolves and gives it +1 &#91;M&#93;.

<details class="rule-ref"><summary title="Core rule 359.3.e.10 · PDF page 58" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.10 · PDF page 58</div></details>

[[Instructions]] that can be partially followed are followed as much as possible and negated otherwise. ^cr-359-3-e-11

**Example:** A player plays a [[Spell|spell]] that says "[[Discard]] 2, then [[Draw|draw]] 2." If their [[Hand|hand]] is empty, the instruction to discard 2 will be negated. They'll still draw 2. If they had 1 [[Card|card]] in hand, they would discard it and draw 2.

<details class="rule-ref"><summary title="Core rule 359.3.e.11 · PDF page 58" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.11 · PDF page 58</div></details>

If the [[Spell|spell]] checks information about a target that is no longer legal or a [[Card|card]] or [[Permanent|permanent]] whose [[Location|location]], [[Zone|zone]], or status has changed such that that information is no longer available, that check returns "null" and all [[Instructions|instructions]] based on it are Ignored. ^cr-359-3-e-12

Examples: A [[Unit|unit]] that is no longer on [[Board|the board]] is treated as having null [[Might]], null [[Costs|cost]], etc. A unit that is no longer on the board has no [[Location|location]], is neither [[Exhaust|exhausted]] nor [[Ready|readied]], etc. Baited Hook says "&#91;1&#93;&#91;C&#93;, &#91;E&#93;: [[Kill]] a [[Friendly|friendly]] unit. Look at the top 5 [[Card|cards]] of your [[Main Deck]]. You may [[Banish|banish]] a unit from among them that has Might up to 1 more than the killed unit and [[Play|play]] it, ignoring its cost. Then [[Recycle|recycle]] the rest." While Baited Hook’s [[Ability|ability]] is on the [[Chain|chain]], an opponent reacts with a [[Spell|spell]] that returns the friendly unit to its owner's [[Hand|hand]]. Because the friendly unit is no longer a legal target, it can't be killed and its Might is treated as null. Baited Hook’s controller looks at the top 5 cards of their Main Deck, but can’t choose any unit from among them. Strike Down reads “Choose an [[Equipped|equipped]] friendly unit. It deals [[Damage|damage]] equal to its Might to an [[Enemy|enemy]] unit. Then [[Detach|detach]] an [[Equipment]] from it.” While Strike Down is on the chain [[Targeting|targeting]] a unit with only one Equipment [[Attached|attached]] to it, that unit has its Equipment detached via Angle Shot. When Strike Down goes to resolve, the targeted unit is no longer legal, so the unit’s Might will return as “null” and the [[Instructions|instructions]] related to it are ignored.

<details class="rule-ref"><summary title="Core rule 359.3.e.12 · PDF page 58" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.12 · PDF page 58</div></details>

If the [[Spell|spell]] checks information about a target that is legal or a [[Card|card]] or [[Permanent|permanent]] whose [[Location|location]], [[Zone|zone]], or status has not changed such that information is no longer available, that information is accessible. ^cr-359-3-e-12-a

<details class="rule-ref"><summary title="Core rule 359.3.e.12.a · PDF page 58" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.12.a · PDF page 58</div></details>

A [[Spell|spell]] or [[Ability|ability]] that moves something to a different [[Zone|zone]] as a [[Costs|cost]] or effect can "look back" at its characteristics before it changes zones. ^cr-359-3-e-13

<details class="rule-ref"><summary title="Core rule 359.3.e.13 · PDF page 58" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.13 · PDF page 58</div></details>

Some [[Instructions|instructions]] may reference [[Game Object|Game Objects]] affected by, or [[Game Action|Game Actions]] performed in, other instructions in a [[Card|card]]. The referenced and referencing instructions are called “linked instructions.” ^cr-359-3-e-14

**Example:** [[Hidden]] Blade reads “[[Kill]] a [[Unit|unit]] at a [[Battlefield|battlefield]]. Its controller draws 2.” The “its” in the second instruction references the unit in the first, so the two [[Instructions|instructions]] of the [[Spell|spell]] are linked.

<details class="rule-ref"><summary title="Core rule 359.3.e.14 · PDF page 58-59" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.14 · PDF page 58-59</div></details>

In order for a later linked instruction to execute, its earlier linked instruction must have executed or been negated. If the earlier linked instruction is Ignored, the later linked instruction will also be Ignored. If any individual target of an earlier linked instruction is ignored, it will also be ignored by any later linked instruction. ^cr-359-3-e-14-a

**Example:** [[Hidden]] Blade reads “[[Kill]] a [[Unit|unit]] at a [[Battlefield|battlefield]]. Its controller draws 2.” If the chosen unit changes [[Zone|zones]] or moves to [[Base|base]] in reaction to Hidden Blade, the [[Spell|spell]] will mistarget and the first instruction will be ignored. If the first instruction is ignored, the second instruction will not execute and the unit’s controller will not [[Draw|draw]] 2.

<details class="rule-ref"><summary title="Core rule 359.3.e.14.a · PDF page 59" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.14.a · PDF page 59</div></details>

If the [[Game Action]] performed in an earlier linked instruction is Negated, this will not affect the later linked instruction, unless the later linked instruction directly references the Game Action being performed. An instruction is Negated if the event its execution generates is replaced or skipped, or if the game action can’t be performed because of a reason other than it being Ignored. ^cr-359-3-e-14-b

**Example:** [[Hidden]] Blade reads “[[Kill]] a [[Unit|unit]] at a [[Battlefield|battlefield]]. Its controller draws 2.” This effect is split into two [[Instructions|instructions]]: killing the unit and the targeted unit’s controller drawing 2. The later linked instruction doesn’t reference an action directly, so it will execute even if the kill action of the earlier linked action is negated.

**Example:** Deathgrip reads “[[Kill]] a [[Friendly|friendly]] [[Unit|unit]]. If you do, give +&#91;M&#93; equal to its [[Might]] to another friendly unit this [[Turn|turn]].” If the friendly unit in question is not killed by Deathgrip because its death is replaced with another event, the later linked instruction will not execute because “if you do” directly references the [[Game Action|game action]].

**Example:** Ride the Wind is a [[Spell|spell]] that reads in part “[[Move]] a [[Friendly|friendly]] [[Unit|unit]] and [[Ready|ready]] it.” Vilemaw’s Lair is a [[Battlefield|battlefield]] that reads “Units can’t move from here to [[Base|base]].” If Ride the Wind is played on a unit at Vilemaw’s Lair choosing the base as its destination, the move instruction will be negated on resolution by the [[Passive Ability|passive ability]] of Vilemaw’s Lair, but the ready instruction will still execute.

<details class="rule-ref"><summary title="Core rule 359.3.e.14.b · PDF page 59" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.14.b · PDF page 59</div></details>

Referencing a [[Game Action|game action]] in this way only refers to the game action being performed and the object or player it was performed on, not the circumstances of its performance. ^cr-359-3-e-14-c

**Example:** A [[Spell|spell]] reads “[[Deal]] 3 to an [[Enemy|enemy]] [[Unit|unit]] at a [[Battlefield|battlefield]]. If you do, [[Heal|heal]] units you [[Control|control]] at the same [[Location|location]] as that unit.” If some but not all of that [[Damage|damage]] is prevented, the later linked instruction will still execute.

**Example:** A [[Spell|spell]] reads “[[Banish]] an [[Enemy|enemy]] [[Unit|unit]] at a [[Battlefield|battlefield]], then [[Play|play]] it to any battlefield. Then if you do, do this: [[Stun|stun]] all enemy units there.” A player plays it [[Targeting|targeting]] a unit that has a passive [[Replacement Effect|replacement effect]] that reads “I enter in [[Base|base]].” The replacement effect causes the unit to enter in base, but this does not [[Prevent|prevent]] the [[Reflexive Trigger|reflexive trigger]] of the spell from being placed on the [[Chain|chain]]. All that matters is that the unit was played.

<details class="rule-ref"><summary title="Core rule 359.3.e.14.c · PDF page 59" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.14.c · PDF page 59</div></details>

A [[Spell|spell]] or [[Ability|ability]] that leaves the [[Chain|chain]] during the process of its resolution will cease further execution of its [[Instructions|instructions]]. This immediately causes the spell or ability to finish resolving. ^cr-359-3-e-15

<details class="rule-ref"><summary title="Core rule 359.3.e.15 · PDF page 59-60" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.15 · PDF page 59-60</div></details>

If a [[Delayed Ability]]’s duration has ended before it was generated, the Delayed Ability is not generated and any [[Instructions|instructions]] related to it are ignored. ^cr-359-3-e-16

**Example:** Targon’s Peak is a [[Battlefield|battlefield]] that reads in part “When you [[Conquer|conquer]] here, [[Ready|ready]] up to 2 [[Rune|runes]] at the end of this [[Turn|turn]].” If Targon’s Peak is conquered during the [[Ending Phase]] after the beginning of the [[Ending Step|ending step]], such as via an effect like Thrill of the [[Hunt]], the [[Delayed Trigger|delayed trigger]] will not be generated.

**Example:** Hostile Takeover is a [[Spell|spell]] that reads “Take [[Control|control]] of an [[Enemy|enemy]] [[Unit|unit]] at a [[Battlefield|battlefield]]. [[Ready]] it.” and “Lose control of that unit and recall it at end of [[Turn|turn]].” If Hostile Takeover is played during the [[Ending Phase]], its delayed [[Triggered Ability|triggered ability]] will not trigger. “At end of turn” and “at the end of this turn” are synonymous, so it will not trigger again.

**Example:** Akshan, Mischievous reads in part “When you [[Play|play]] me, if you paid the [[Additional Cost|additional cost]], [[Move|move]] an [[Enemy|enemy]] [[Gear|gear]] to your [[Base|base]]. You [[Control|control]] it until I leave [[Board|the board]]. If it's an [[Equipment]], [[Attach|attach]] it to me.” If Akshan leaves the board in reaction to his [[Play Effect|play effect]], the [[Delayed Passive Ability|delayed passive ability]] “You control it until I leave the board,” will not be generated. You will not gain control of the targeted gear even for a moment.

<details class="rule-ref"><summary title="Core rule 359.3.e.16 · PDF page 60" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.e.16 · PDF page 60</div></details>

### Referents

^cr-359-3-f

<details class="rule-ref"><summary title="Core rule 359.3.f · PDF page 60" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.f · PDF page 60</div></details>

Some information used by [[Ability|abilities]] is referenced from the source of those abilities, or from one or more targets of a [[Spell|spell]] or ability. This can usually be recognized by the presence of words like “here,” “my,” or “its.” ^cr-359-3-f-1

<details class="rule-ref"><summary title="Core rule 359.3.f.1 · PDF page 60" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.f.1 · PDF page 60</div></details>

Information referenced in an instruction in this way will be checked on execution of the instruction, unless specified otherwise by the effect. ^cr-359-3-f-2

Examples: A player moves Yasuo, Remorseful to an occupied [[Enemy|enemy]] [[Battlefield|battlefield]] and initiates [[Combat|combat]] there. In reaction to the Yasuo, Remorseful [[Attack Trigger|attack trigger]], their opponent plays Fight or Flight from facedown [[Targeting|targeting]] Yasuo, [[Movement|moving]] him back to [[Base|base]]. When the attack trigger resolves, “here” is no longer the battlefield where combat is ongoing and the attack trigger mistargets. In reaction to a Yasuo, Remorseful attack trigger, an opponent plays Stupefy targeting Yasuo. When Yasuo’s attack trigger resolves, it will [[Deal|deal]] [[Damage|damage]] equal to his current [[Might]] of 5.

When a referent checks information on execution of the instruction related to a target, and that target isn’t legal, that referent will return “null” and all [[Instructions|instructions]] related to it will be ignored. ^cr-359-3-f-2-a

<details class="rule-ref"><summary title="Core rule 359.3.f.2.a · PDF page 60" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.f.2.a · PDF page 60</div></details>

Some information used by [[Triggered Ability|triggered abilities]] is referenced from the trigger condition of the [[Ability|ability]]. This information is checked when the trigger condition is fulfilled. ^cr-359-3-f-3

**Example:** Lillia, Fae Fawn reads “when I [[Move|move]] from a [[Location|location]], [[Play|play]] a 3 &#91;M&#93; Sprite [[Token|token]] with [[Temporary]] there.” If Lillia moves to a [[Battlefield|battlefield]], her [[Triggered Ability|triggered ability]] will be placed on the [[Chain|chain]] and it will note the location she moved from when it does so. If she moves to a non-board [[Zone|zone]] in reaction to the triggered ability on the chain, it will not affect where the Sprite token will be played when the triggered ability resolves.

<details class="rule-ref"><summary title="Core rule 359.3.f.3 · PDF page 60" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.f.3 · PDF page 60</div></details>

In the case of a delayed [[Triggered Ability|triggered ability]], the information is referenced when the triggered ability is created unless specified otherwise. ^cr-359-3-f-3-a

<details class="rule-ref"><summary title="Core rule 359.3.f.3.a · PDF page 60" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.f.3.a · PDF page 60</div></details>

In the case of a [[Linked Ability|linked ability]] that references information from a linked [[Triggered Ability|triggered ability]], that information may be referenced from the trigger condition of the linked triggered ability if specified. ^cr-359-3-f-3-b

**Example:** Iascylla reads “When I [[Hold|hold]], at the start of your next [[Main Phase]], you may [[Move|move]] an [[Enemy|enemy]] [[Unit|unit]] to this [[Battlefield|battlefield]].” The “this battlefield” in her delayed [[Triggered Ability|triggered ability]] refers to the battlefield she held, and so will be referenced from the trigger condition, when the triggered ability is generated.

<details class="rule-ref"><summary title="Core rule 359.3.f.3.b · PDF page 61" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 359.3.f.3.b · PDF page 61</div></details>

Some information used by the effect of a [[Triggered Ability|triggered ability]] is referenced from the triggered ability itself, such as “[[Enemy|enemy]]” and “[[Friendly|friendly]]” status. This information is checked on execution of the referencing instruction. ^cr-359-3-f-4

**Example:** Yasuo, Remorseful reads “when I attack, [[Deal|deal]] [[Damage|damage]] equal to my [[Might]] to an [[Enemy|enemy]] [[Unit|unit]] here.” Yasuo moves to an occupied enemy [[Battlefield|battlefield]] and his [[Attack Trigger|attack trigger]] goes on the [[Chain|chain]]. In reaction to the attack trigger, the [[Defender|defending]] player plays a [[Hidden|hidden]] Hostile Takeover and gains [[Control|control]] of Yasuo. The [[Triggered Ability|triggered ability]] is unaffected by Yasuo changing controllers, and “enemy” is in reference to the triggered ability itself, so it will resolve with no issue.

**Example:** In reaction to the same Yasuo, Remorseful trigger, say the [[Defender|defending]] player had instead played a [[Spell|spell]] that reads “&#91;[[Reaction (Keyword)|Reaction]]&#93;. Gain [[Control|control]] of a [[Triggered Ability|triggered ability]]. You may make new choices for it.” They chose the [[Attack Trigger|attack trigger]]. When Yasuo’s attack trigger resolves, if they didn’t make new choices for the trigger, the controller of the triggered ability will no longer be an [[Enemy|enemy]] to the targeted [[Unit|unit]], so the triggered ability will mistarget and do nothing. If they instead chose Yasuo with the attack trigger, he would be an enemy unit to the triggered ability and so it would [[Deal|deal]] [[Damage|damage]] equal to his [[Might]] to himself.
