### Step 1: The Combat Showdown Step

^cr-466

<details class="rule-ref"><summary title="Core rule 466 · PDF page 101" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 466 · PDF page 101</div></details>

[[Combat]] will open in one of two ways: when a Combat and [[Showdowns|Showdown]] are staged at the same [[Battlefield]] and [[Turn|the turn]] player initiates the Showdown; or when the turn is in a [[Showdown Open State]] and a Combat is staged at the Battlefield where the current Showdown is ongoing. ^cr-466-1

See [[Cleanups#^cr-318|Cleanups]] for more information.

<details class="rule-ref"><summary title="Core rule 466.1 · PDF page 101" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 466.1 · PDF page 101</div></details>

When [[Combat]] opens, it either opens with a Combat [[Showdowns|Showdown]], or the current Showdown becomes a Combat Showdown. ^cr-466-2

<details class="rule-ref"><summary title="Core rule 466.2 · PDF page 101" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 466.2 · PDF page 101</div></details>

The following [[Task|Tasks]] become Outstanding, in the order described: ^cr-466-2-a

<details class="rule-ref"><summary title="Core rule 466.2.a · PDF page 101" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 466.2.a · PDF page 101</div></details>

1. Start of [[Combat|combat]] effects happen now. If the Combat opened with a Combat [[Showdowns|Showdown]], start of showdown effects happen simultaneously. ^cr-466-2-b

<details class="rule-ref"><summary title="Core rule 466.2.b · PDF page 101" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 466.2.b · PDF page 101</div></details>

2. Establish who is [[Attacker]] and who is [[Defender]]. ^cr-466-2-c

<details class="rule-ref"><summary title="Core rule 466.2.c · PDF page 101" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 466.2.c · PDF page 101</div></details>

The [[Attacker]] is the player whose [[Unit|unit]](s) applied the [[Contested]] status to the [[Battlefield]]. ^cr-466-2-c-1

<details class="rule-ref"><summary title="Core rule 466.2.c.1 · PDF page 101" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 466.2.c.1 · PDF page 101</div></details>

If a [[Showdowns|showdown]] opens as part of [[Combat|combat]], this player gains [[Focus]] as the showdown begins. ^cr-466-2-c-1-a

<details class="rule-ref"><summary title="Core rule 466.2.c.1.a · PDF page 101" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 466.2.c.1.a · PDF page 101</div></details>

If a [[Showdowns|showdown]] was already ongoing when the [[Combat|combat]] opens, the player who has [[Focus]] maintains their Focus. ^cr-466-2-c-1-b

<details class="rule-ref"><summary title="Core rule 466.2.c.1.b · PDF page 101" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 466.2.c.1.b · PDF page 101</div></details>

The [[Defender]] is the player who did not apply the [[Contested]] status to the [[Battlefield]]. ^cr-466-2-c-2

<details class="rule-ref"><summary title="Core rule 466.2.c.2 · PDF page 101" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 466.2.c.2 · PDF page 101</div></details>

The [[Attacker|attacker]] and [[Defender|defender]] gain the Attacker or Defender designation now, as appropriate. [[Unit|Units]] at the [[Contested]] [[Battlefield]] controlled by the Attacker or Defender gain the Attacker or Defender designation now, as appropriate. ^cr-466-2-c-3

<details class="rule-ref"><summary title="Core rule 466.2.c.3 · PDF page 101" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 466.2.c.3 · PDF page 101</div></details>

If a [[Unit]] controlled by the [[Attacker]] or [[Defender]] becomes present at this [[Battlefield]] after this moment, it will gain the Attacker or Defender designation during the [[Cleanups|Cleanup]] phase following the action that caused it to become present, as appropriate for its controller. ^cr-466-2-c-3-a

<details class="rule-ref"><summary title="Core rule 466.2.c.3.a · PDF page 101" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 466.2.c.3.a · PDF page 101</div></details>

3. Add items to the [[Combat]] [[Chain]] if establishing [[Attacker]] and [[Defender]] has caused [[Triggered Ability|Triggered Abilities]] to become Pending. ^cr-466-2-d

<details class="rule-ref"><summary title="Core rule 466.2.d · PDF page 101" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 466.2.d · PDF page 101</div></details>

The [[Attacker|Attacking]] player, who has [[Focus]], places [[Triggered Ability|Triggered Abilities]] on the [[Chain]] first, followed by all non-Defender players in [[Turn]] Order, followed by the [[Defender|Defending]] Player. ^cr-466-2-d-1

<details class="rule-ref"><summary title="Core rule 466.2.d.1 · PDF page 101" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 466.2.d.1 · PDF page 101</div></details>

The State Closes if a [[Combat]] [[Chain]] was created. ^cr-466-2-e

<details class="rule-ref"><summary title="Core rule 466.2.e · PDF page 101" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 466.2.e · PDF page 101</div></details>

Otherwise the [[Combat]] [[Showdowns|Showdown]] continues, with the State Open as normal. ^cr-466-2-e-1

<details class="rule-ref"><summary title="Core rule 466.2.e.1 · PDF page 101" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 466.2.e.1 · PDF page 101</div></details>

Players proceed with any [[Play|play]] on the [[Chain]] as normal. ^cr-466-2-f

### Step 2: The Combat Damage Step

^cr-467

<details class="rule-ref"><summary title="Core rule 467 · PDF page 101" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 467 · PDF page 101</div></details>

If both [[Attacker|Attacking]] and [[Defender|Defending]] [[Unit|units]] remain at this [[Battlefield|battlefield]], the following [[Task|Tasks]] become Outstanding, in the specified order: ^cr-467-1

<details class="rule-ref"><summary title="Core rule 467.1 · PDF page 102" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 467.1 · PDF page 102</div></details>

1. When the [[Showdowns|Showdown]] closes, Attackers and Defenders resolve [[Combat]] [[Damage]] at the [[Battlefield]] that was attacked, using their current [[Might]]. ^cr-467-2

<details class="rule-ref"><summary title="Core rule 467.2 · PDF page 102" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 467.2 · PDF page 102</div></details>

Sum the [[Might]] of all [[Attacker|Attacking]] [[Unit|Units]]. ^cr-467-2-a

<details class="rule-ref"><summary title="Core rule 467.2.a · PDF page 102" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 467.2.a · PDF page 102</div></details>

Sum the [[Might]] of all [[Defender|Defending]] [[Unit|Units]]. ^cr-467-2-b

<details class="rule-ref"><summary title="Core rule 467.2.b · PDF page 102" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 467.2.b · PDF page 102</div></details>

Starting with the [[Attacker]], each player assigns an amount of [[Damage|damage]] equal to their summed [[Might]] among the other's [[Unit|Units]]. ^cr-467-2-c

<details class="rule-ref"><summary title="Core rule 467.2.c · PDF page 102" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 467.2.c · PDF page 102</div></details>

Assigning [[Damage]] is not Dealing Damage. ^cr-467-2-c-1

<details class="rule-ref"><summary title="Core rule 467.2.c.1 · PDF page 102" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 467.2.c.1 · PDF page 102</div></details>

When all [[Damage]] is assigned, it will be Dealt simultaneously. These actions are not synonymous. ^cr-467-2-c-1-a

<details class="rule-ref"><summary title="Core rule 467.2.c.1.a · PDF page 102" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 467.2.c.1.a · PDF page 102</div></details>

[[Ability|Abilities]] or effects may influence the order in which [[Damage|damage]] is assigned. ^cr-467-2-c-2

Reminder: [[Lethal Damage]] is non-zero [[Damage|damage]] equaling or exceeding the [[Might]] of a [[Unit]].

<details class="rule-ref"><summary title="Core rule 467.2.c.2 · PDF page 102" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 467.2.c.2 · PDF page 102</div></details>

[[Unit|Units]] must have [[Lethal Damage|lethal damage]] assigned to them in full before [[Damage|damage]] is assigned to a different Unit. ^cr-467-2-c-3

**Example:** If a player has 5 [[Damage|damage]] to distribute among four 3 [[Might]] [[Unit|units]], they may not choose to assign 2 damage to one of the units and 1 damage to each of the remaining 3. They must assign 3 damage to one, and the remaining 2 to another.

<details class="rule-ref"><summary title="Core rule 467.2.c.3 · PDF page 102" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 467.2.c.3 · PDF page 102</div></details>

[[Unit|Units]] cannot have more [[Damage|damage]] assigned to them than the minimum required to constitute [[Lethal Damage|lethal damage]] unless no further units remain to have damage assigned to them. ^cr-467-2-c-4

**Example:** If a player has 5 [[Damage|damage]] to distribute among four 3 [[Might]] [[Unit|units]] and those units each have 1 damage already marked on them, that player may not assign more than 2 damage to any of those units.

<details class="rule-ref"><summary title="Core rule 467.2.c.4 · PDF page 102" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 467.2.c.4 · PDF page 102</div></details>

If the [[Damage|damage]] assigned to a [[Unit]] is modified to or replaced by an amount of damage larger than the initial value, the assigning player must choose the minimum applied value such that the unit would take [[Lethal Damage|lethal damage]]. ^cr-467-2-c-4-a

**Example:** A [[Unit|unit]] with 3 &#91;M&#93; is being assigned [[Damage|damage]] in the [[Combat|combat]] damage step. There are other units without damage assigned to them with the same controller. The unit has a [[Delayed Replacement|delayed replacement]] effect applied to it that reads “Double all damage that would be dealt to it this [[Turn|turn]].” When assigning damage, the assigning player can only choose to assign 1 or 2 damage to this unit—when doing so, the assigned damage is doubled to 2 or 4 damage respectively. The minimum applied value such that the unit would take [[Lethal Damage|lethal damage]] in this way is 4 damage.

<details class="rule-ref"><summary title="Core rule 467.2.c.4.a · PDF page 102" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 467.2.c.4.a · PDF page 102</div></details>

When assigning [[Damage|damage]] in this way, [[Passive Ability|passive abilities]] and [[Replacement Effect|replacement effects]] that would apply to the resulting damage are considered to apply to the assignment instead. ^cr-467-2-c-5

**Example:** A [[Unit|unit]] with 2 &#91;M&#93; is being assigned [[Damage|damage]] in the [[Combat|combat]] damage step. The unit has “[[Prevent|prevent]] the first 3 damage I would take each combat.” The unit would need to be assigned 5 damage in order to have [[Lethal Damage|lethal damage]] assigned to it.

**Example:** The [[Attacker|attacking]] player is assigning their 3 &#91;M&#93; worth of [[Damage|damage]] to two [[Defender|defending]] [[Unit|units]] with 2 &#91;M&#93; each. One of the units has a [[Delayed Replacement|delayed replacement]] effect applied to it that reads “Double all damage that would be dealt to it this [[Turn|turn]].” The attacking player assigns two damage to the other defending unit, then when assigning damage to the unit with the delayed replacement effect they assign 2 damage to it; 1 damage that doubles to 2 damage as it is assigned to the unit. When that damage is dealt, it doesn’t get doubled again—the doubling is considered to have already happened during damage assignment.

**Example:** The [[Attacker|attacking]] player is assigning their 3 &#91;M&#93; worth of [[Damage|damage]] to a 2 &#91;M&#93; [[Unit|unit]]. That unit has a [[Prevent|prevent]] value of two being applied to it, as well as the effect of Lotus Trap, doubling the damage dealt to them. Both of these [[Replacement Effect|replacement effects]] apply to the assignment of damage, in the order of the controller of the 2 &#91;M&#93; unit’s choice. If they choose to order the replacement effects so that the prevent value is applied first, the unit will prevent 2 of the assigned damage, then the last 1 point of damage will be doubled to 2. The unit will have 4 damage assigned to it. When damage is dealt, the unit will take 2 damage. If they choose the other order, the unit will have 6 damage assigned to it, 2 of which will be prevented. When damage is dealt, the unit will take 4 damage.

<details class="rule-ref"><summary title="Core rule 467.2.c.5 · PDF page 102-103" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 467.2.c.5 · PDF page 102-103</div></details>

A player must obey all requirements and restrictions on [[Damage|damage]] assignment if able. ^cr-467-2-c-6

**Example:** A player is assigning [[Damage|damage]] to the following [[Unit|units]]: a unit with [[Tank]] ("I must be assigned [[Combat|combat]] damage first."); a unit with [[Backline]] ("I must be assigned combat damage last."); and another unit without any [[Ability|abilities]]. That player must assign combat damage first to the unit with Tank, then to the unit with no abilities, then to the unit with Backline.

<details class="rule-ref"><summary title="Core rule 467.2.c.6 · PDF page 103" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 467.2.c.6 · PDF page 103</div></details>

If multiple [[Unit|Units]] have [[Ability|abilities]] or effects that require a player to assign them [[Damage|damage]] with the same [[Priority|priority]], that player may assign damage to those units in any order. ^cr-467-2-c-7

**Example:** A player is assigning [[Damage|damage]] to the following [[Unit|units]]: two units with [[Tank]] ("I must be assigned [[Combat|combat]] damage first.") and one unit with no [[Ability|abilities]]. That player chooses one of the units with Tank and assigns combat damage to it. Then they must assign any remaining damage first to the other unit with Tank, then to the unit with no abilities.

<details class="rule-ref"><summary title="Core rule 467.2.c.7 · PDF page 103" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 467.2.c.7 · PDF page 103</div></details>

If a [[Unit]] has one or more [[Ability|Abilities]] or effects applying to it that demand it be assigned [[Damage|damage]] in a specific way that is exclusionary, then the assigning player chooses only one of those abilities to apply when assigning damage. ^cr-467-2-c-8

**Example:** Caitlyn, Patrolling with the [[Backline]] [[Ability|ability]] ("I must be assigned [[Combat|combat]] [[Damage|damage]] last.") has been given the [[Tank]] ability ("I must be assigned combat damage first."). A player is assigning damage to this Caitlyn with Tank and two [[Unit|units]] with no abilities. That player can’t fulfill both of Caitlyn’s damage requirements, so they may choose to assign damage to Caitlyn first, fulfilling the Tank requirement, or last, fulfilling the Backline requirement. They can’t choose to apply damage to Caitlyn in between the other two units, because that wouldn’t fulfill either requirement.

<details class="rule-ref"><summary title="Core rule 467.2.c.8 · PDF page 103" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 467.2.c.8 · PDF page 103</div></details>

If there is more than one [[Unit|unit]] in which this situation applies to, each unit is dealt with individually. The assigning player chooses which [[Ability|ability]] or effect applies, and then resolves the assignment. If this creates a situation where now more than one unit must be assigned with the same [[Priority|priority]], those units may be assigned [[Damage|damage]] in any order as normal within that priority. ^cr-467-2-c-9

**Example:** Two copies of Caitlyn, Patrolling with the [[Backline]] [[Ability|ability]] ("I must be assigned [[Combat|combat]] [[Damage|damage]] last.") have been given the [[Tank]] ability ("I must be assigned combat damage first."). A player assigning damage to these two Caitlyns and one [[Unit|unit]] with no abilities could choose to fulfill both Caitlyns’ Tank requirements by assigning them both damage before the other unit.

<details class="rule-ref"><summary title="Core rule 467.2.c.9 · PDF page 103-104" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 467.2.c.9 · PDF page 103-104</div></details>

If a [[Unit|unit]] cannot be dealt [[Damage|damage]], then no amount of damage can be considered lethal. Such a unit is exempt from any considerations of mandatory assignment. ^cr-467-2-c-10

**Example:** Kayn, Unleashed says “If I have moved twice this [[Turn|turn]], I don't take [[Damage|damage]].” While Kayn can’t take damage, it is ignored for the purposes of assigning [[Lethal Damage|lethal damage]] [[In Combat|in combat]].

**Example:** Counter Strike says “Choose a [[Unit|unit]]. The next time that unit would be dealt [[Damage|damage]] this [[Turn|turn]], [[Prevent|prevent]] it.” The unit in question has a [[Replacement Effect|replacement effect]] applied to it, but it still can be dealt damage. Thus, it is not exempt from considerations of mandatory assignment.

<details class="rule-ref"><summary title="Core rule 467.2.c.10 · PDF page 104" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 467.2.c.10 · PDF page 104</div></details>

[[Deal]] [[Damage]] to each [[Unit|unit]] equal to the amount assigned to it. ^cr-467-2-d

<details class="rule-ref"><summary title="Core rule 467.2.d · PDF page 104" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 467.2.d · PDF page 104</div></details>

2. Skip the FEPR process and cancel any [[Outstanding Task|outstanding tasks]]. Proceed to the Resolution Step. ^cr-467-3

<details class="rule-ref"><summary title="Core rule 468.7 · PDF page 105" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 468.7 · PDF page 105</div></details>

Remove [[Attacker]] and [[Defender]] Designation from all [[Unit|Units]] and Players. ^cr-468-7-a
