# Multiple Card Types

[[Start Here|Home]] · [[Concept Index|Find a concept]] · [[Core Rules Index|Core rules]]

<span title="Core rule 177"></span> ^cr-177

<details class="rule-ref"><summary title="Core rule 177 · PDF page 27" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 177 · PDF page 27</div></details>

[[Game Object|Game Objects]] can have multiple types. ^cr-178

<details class="rule-ref"><summary title="Core rule 178 · PDF page 27" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 178 · PDF page 27</div></details>

A [[Game Object]] that is more than one type has the properties of all of their types, except where they are mutually exclusive. ^cr-178-1

<details class="rule-ref"><summary title="Core rule 178.1 · PDF page 27" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 178.1 · PDF page 27</div></details>

Regardless of a [[Game Object|Game Objects]]’ other types, there are some properties that are true of Game Objects of certain types. These properties take precedence when properties are mutually exclusive. ^cr-178-1-a

<details class="rule-ref"><summary title="Core rule 178.1.a · PDF page 27" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 178.1.a · PDF page 27</div></details>

If a [[Game Object]] is a [[Unit]], regardless of its other types, it has [[Might]], can have [[Damage|damage]] marked on it, enters [[Exhaust|exhausted]], and can be played to any valid [[Location|location]]. ^cr-178-1-a-1

<details class="rule-ref"><summary title="Core rule 178.1.a.1 · PDF page 27" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 178.1.a.1 · PDF page 27</div></details>

It will not be recalled to [[Base|base]] from a [[Battlefield]] in step 5 of a [[Cleanups|cleanup]]. ^cr-178-1-a-1-a

<details class="rule-ref"><summary title="Core rule 178.1.a.1.a · PDF page 27" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 178.1.a.1.a · PDF page 27</div></details>

If a [[Game Object]] is a [[Rune]], regardless of its other types, it will be recycled to the [[Rune Deck]]. ^cr-178-1-a-2

<details class="rule-ref"><summary title="Core rule 178.1.a.2 · PDF page 27" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 178.1.a.2 · PDF page 27</div></details>

A [[Game Object]] that is more than one type maintains all of the permissions of all types. ^cr-178-2

<details class="rule-ref"><summary title="Core rule 178.2 · PDF page 27" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 178.2 · PDF page 27</div></details>

If a [[Game Object]] is a [[Unit]], it has the [[Standard Move|standard move]] inherent [[Ability|ability]]. ^cr-178-2-a

<details class="rule-ref"><summary title="Core rule 178.2.a · PDF page 27" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 178.2.a · PDF page 27</div></details>

It can [[Move|move]] and become located at a [[Battlefield]]. ^cr-178-2-a-1

<details class="rule-ref"><summary title="Core rule 178.2.a.1 · PDF page 27" aria-label="Show source rule">ⓘ</summary><div class="rule-tooltip">Core rule 178.2.a.1 · PDF page 27</div></details>

A [[Game Object]] that is more than one type can be affected by [[Game Effect|Game Effects]] that modify or interact with any of its types. ^cr-178-3

**Example:** A [[Unit|unit]] that is also a [[Gear|gear]] can be affected by [[Spell|spells]] and [[Ability|abilities]] like the Ruination or Thermo Beam that say “[[Kill]] all units,” or “Kill all gear.” A unit that is also a gear can be targeted by spells and abilities like Vengeance or Rocket Barrage that say “Kill a unit,” or “Kill a gear.”
