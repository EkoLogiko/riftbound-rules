## Source

[[Sources/RiftboundCoreRulesRUP5_En_EN.pdf|Riftbound Core Rules PDF]], last updated 9 October 2026, 142 pages. This vault uses the supplied document rather than a live online rules source.

## Completeness

All **2,494 numbered entries** are mapped to a canonical block across **161 topic notes**. There are **111 additional concept pages**. Examples, exceptions, reminders, quoted card text, and subrules are retained. Main and subsection labels become headings. Source numbers are in tooltip details and hidden block identifiers.

`Maintenance/core-rules-manifest.json` records every source entry, its original extracted text, PDF page, destination note, and block identifier, together with the source PDF SHA-256. It is a maintenance file, so it does not create thousands of extra searchable rule notes.

## Editorial approach

The rule prose preserves the source wording and capitalization. PDF line wraps are removed; related subrules are presented as readable paragraphs under topic headings. Examples have their own paragraphs. Source cross-references become descriptive links to the corresponding rule block. Concept titles and aliases use consistent terminology; links preserve the displayed source wording. Related-concept lists are navigation aids, not additional game rules.

A few misleading source cross-references were repaired for navigation: references labelled Chosen Champion, Signature cards, Rune Deck, and Playing or Activating Abilities now point to those passages. Their original and repaired identifiers are recorded in the manifest. The game-rule prose is unchanged.

Concept notes embed the canonical rule passages; additional example paragraphs are also included. Edit the canonical topic note first. If an example is edited, update its repeated concept-page copy too. The manifest preserves the original source text for checking future changes.

## References and device support

Hover over ⓘ on desktop to see the rule number and PDF page. Tap it on mobile to reveal the reference. This uses ordinary HTML details and a CSS snippet, with no community plugin. Obsidian sanitizes HTML and does not render Markdown inside HTML, so the rule links are kept outside the reference widgets. See [Obsidian HTML documentation](https://obsidian.md/help/html) and [CSS snippets documentation](https://obsidian.md/help/snippets).

The reference number is hidden in Reading view until hovered or expanded. Source mode necessarily displays the underlying markup. Search may also find stored identifiers. The phone interface has not been tested in the user's installed Obsidian app.
